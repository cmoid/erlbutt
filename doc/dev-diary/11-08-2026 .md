## [ssb_git](https://github.com/cmoid/ssb_git)

  This is now a plugin. If you build it separately it will pull in erlbutt as a dependency. If it's present as a sibling next to erlbutt, erlbutt builds will include it as a plugin. It's a good example that validates the plugin model in erlbutt that comes from `SSB`. All the existing git messages in the logs work fine with no changes. It also includes an emacs mode for use in maxbutt. Lots of detail exists in the README.

## [erlbutt](https://github.com/cmoid/erlbutt)

  I just pushed a [v0.2.0](https://github.com/cmoid/erlbutt/releases/tag/v0.2.0) release of #erlbutt. I spent some time re-working all the many docs into a structure that others might find useful, with links to the places where I've extended the protocol. There's details on converting an existing `SSB` log to #erlbutt. Erlbutt uses the same log format as `SSB` but uses a separate log file for each feed. My opinion is that this makes for a much more robust and flexible flume like model that scales better.

  The apps that come packaged, silkpurse, ssb_git, and plumtree, can be left out of a package if one wants a simple `ssb` replicator node that acts as a pub. Plumtree, I believe can also provide the basis for a cluster of erlbutt nodes that sync internally yet communicate externally using muxrpc.

  BEAM can be scaled down also, so I'll probably look into how small an erlbutt node I can make that is still useful as a replicator.

  No real progress on this. It's been really good lately to see more interest in this technology. Part of what motivates my recent work on erlbutt was a fear that the existing clients would atrophy and degrade and eventually become unusable. Tildefriends was like the last man standing.
