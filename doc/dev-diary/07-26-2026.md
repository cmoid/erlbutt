## [erlbutt](https://github.com/cmoid/erlbutt)

All roads lead to sqllite :) I spent most of this past week reviewing all the places where I'm using persistence in erlbutt and coming up with an approach. I spent a couple of days going back and forth with Claude and finally reached a [good place](https://github.com/cmoid/erlbutt/blob/main/doc/research/persistence.md). This is where the AI really shines, mainly because of it's ability to review what's out there. 

The key design point is that the feeds are stored per user in the same `log.offset` format used in the main patchX apps. They are stored along with any archive files, should the feed get too large, and what's called a *hint* file. This is an idea I stole from bitcask, my favorite KV store.

Sqlite is used for all the derived data, views and so forth. This data can be destroyed anytime as it can always be reproduced from the feeds.

We're also nicely maintaining the separation of concerns in having a foundation layer on top of which plugins are installed. Some of the views have been deemed core as they are usable by multiple apps, but I've abstracted out the particulars of message internals. So we have `ssb_links`, `ssb_feed_meta` and `ssb_social_graph`. Having these makes many of the views in the silkpurse app just thin adapters.

Anyway if interested I wrote up a [persistence section](https://github.com/cmoid/erlbutt/blob/main/doc/project.md#persistence) in the project notes.

As an aside, I forked the sqllite NIF I'm using, mainly because the published version in the hex package manager doesn't have a link to a tagged build. They have checksums but only a general link to GH. It was a real WTF to me as I'm used to reproducible builds. Anyway it's awesome, it's SQL, I'm sure it will prove useful.

What's nice also is that the immutable layer is such that all I need do is add blobs per feed and I can do the willow drop export thing. The HIPAA folks would be proud to see someone put the P for portable back in there.

## maxbutt

I also added an admin app in erlbutt that talks muxrpc, and modified maxbutt to make use of that. Maxbutt runs on top of distel so it's right on the BEAM and doesn't need muxrpc but this might be useful down the road. It runs as owner, making the same local/remote distinction that silkpurse does. In other words, only the Earl of Butt can use it.
